## 0\. John Romero в одном абзаце { #0-john-romero }




John Romero — один из основателей id Software и один из ключевых людей раннего PC-FPS. Его сильнейшая зона — не graphics architecture уровня John Carmack, а превращение технологии в игру: production tools, редакторы, level design, movement, flow, encounter rhythm, deathmatch и быстрый playtest-loop. В ранней id эта связка дала Commander Keen, Wolfenstein 3D, DOOM и Quake; в Ion Storm абсолютная дизайнерская свобода обнажила слабые стороны Romero в scope и large-team production на Daikatana, но одновременно именно он создал условия, в которых Warren Spector смог сделать Deus Ex. Поздняя карьера прошла через mobile, MMO и social games, а с SIGIL и SIGIL II Romero вернулся к исходной силе — плотному дизайну уровней внутри ограниченного ruleset. На 2026 год Romero Games продолжает работу над современным FPS после rescope, а сам Romero параллельно делает DOOM II-проект HELLION.

## 1\. Краткая карточка { #1 }




**Полное имя:** John Romero  

**Основная роль в истории игр:** программист, tools programmer, level designer, game designer, project lead, producer, сооснователь id Software и Ion Storm  

**Главные проекты:** Commander Keen, Wolfenstein 3D, DOOM, DOOM II, Quake, Daikatana, SIGIL, SIGIL II  

**Главная специализация:** превращение технической возможности в непосредственно интересный игровой процесс и пространство  

**Ключевая дизайнерская область:** level design, FPS movement, flow, exploration, deathmatch  

**Ключевая инженерная область:** игровые редакторы и production tools  

**Ключевой исторический партнёр:** John Carmack  

**Другой важнейший партнёр:** Tom Hall  

**Текущая студия:** Romero Games  

**Текущее направление на 2026 год:** новый современный FPS + классический Doom II-проект HELLION  

**Поздняя авторская линия:** SIGIL → SIGIL II → HELLION → заявленный в перспективе новый Quake episode

### 1\. Главный тезис о Romero { #1-romero }




Неправильное упрощение:




```
John Carmack
→ гений
→ написал движки

John Romero
→ чувак с длинными волосами
→ сделал несколько карт
→ зазвездился
→ сделал Daikatana
```




Это сильно искажает историю.




Гораздо точнее:




#### John Romero был вторым двигателем ранней id Software. { #john-romero-id-software }




Carmack обычно отвечал на вопрос:




> Что компьютер технически способен сделать?




Romero:




> Что игроку будет интересно делать внутри этой технологии?




Его реальная область значительно шире level design:




```
programming
+
tools
+
editors
+
level design
+
gameplay
+
production
+
multiplayer
+
external development
+
community
```




Ключевая формула ранней id:




```
Carmack
↓
расширяет пространство технически возможного

Romero
↓
моментально превращает новую возможность
в playable game

Hall
↓
добавляет мир / персонажей / fiction

Adrian Carmack
↓
создаёт визуальную идентичность
```




Когда эта система работала синхронно, появились:




```
Commander Keen
Wolfenstein 3D
DOOM
```




На Quake синхронизация ломается.

### 2\. Romero до id { #2-romero-id }




Romero родился в 1967 году.




Игры начал программировать ещё подростком.




Основная ранняя платформа:




#### Apple II. { #apple-ii }




Он самостоятельно изучал:




```
BASIC
↓
6502 assembly
```




Ассемблер был нужен потому, что быстрые arcade-style игры требовали производительности, которой BASIC не давал.




До полноценной работы в индустрии Romero уже написал множество небольших игр.




Одной из ранних опубликованных работ была:




#### Scout Search. { #scout-search }

### 3\. Origin Systems { #3-origin-systems }




В 1987 году Romero попадает в:




#### Origin Systems. { #origin-systems }




Работает над портированием и игровым программированием.




Один из проектов:




```
2400 A.D.
Apple II
→ Commodore 64 port
```




Также оказывается рядом с проектами и людьми будущей Looking Glass-школы.




Здесь важна историческая развилка:

То есть Romero потенциально мог оказаться в линии:




```

```




Но пошёл другим путём.




Позже две школы всё равно косвенно сойдутся через Ion Storm и Deus Ex.

### 5\. Dangerous Dave { #5-dangerous-dave }




В 1988 году Romero делает:




#### Dangerous Dave. { #dangerous-dave }




Это ещё не id Software.




Но проект критически важен для его будущей инженерной философии.




Ему нужны уровни.




Вместо ручного кодирования каждой карты Romero начинает делать редактор.




Из этой линии вырастет:




#### TEd — Tile Editor. { #ted-tile-editor }




Разные поколения TEd позже использовались примерно в десятках выпущенных игр.




Главный принцип Romero формируется очень рано:




```
обычный программист
делает уровень

tools programmer
делает систему,
которая позволяет быстро сделать
100 уровней
```




Это будет одним из его главных скрытых вкладов в id.

```
↓
Tom Hall начинает работать с ними

```




Romero не «попал в id».

## 15\. Навигационные выводы — быстрые связи между эпохами { #15 }




### Technology → tools → game { #technology-tools-game }




Основная ранняя связка файла: Carmack расширяет технически возможное, Romero строит инструменты и превращает новую возможность в непосредственно работающий игровой процесс.




### id → Ion Storm { #id-ion-storm }




Ion Storm является сознательной реакцией на опыт id: вместо принципа «technology first» Romero и Hall формулируют `Design Is Law`. Daikatana показывает, что абсолютный design-first без жёсткого scope и production discipline так же опасен, как технологический диктат.




### Daikatana → поздний Romero { #daikatana-romero }




Главная поздняя дуга базы — переход от feature breadth и гигантского scope к ограниченному ruleset, плотности и быстрым итерациям. BLACKROOM уже останавливается при отсутствии достаточного proof, а SIGIL/SIGIL II строятся вокруг намеренно ограниченного инструментария Doom.




### Community как постоянная линия { #community_1 }




От Doom WADs, TeamTNT и Final Doom до собственного возвращения в статус community mapper через SIGIL: Romero последовательно воспринимает сообщество не как периферию индустрии, а как источник контента, людей и новых форм жизни старых игр.
